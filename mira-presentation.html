Mira Prompts
Master Specification

The exact architecture, business model, and technical decisions behind the world's most beautiful AI prompt library. Built on "Ponytail" and "Caveman" engineering principles.

1. Overview

Name: Mira Prompts

Version: 1.0.0

Description: A premium, monetized platform for discovering, saving, and copying exact formulas used to generate stunning AI images across Midjourney, Flux, and ChatGPT.

Core Objectives

  • Provide a flawless, visually arresting Masonry grid experience (Pinterest-style).
  • Monetize "Prime" and "Featured" prompts via Razorpay subscriptions (Monthly/Yearly/Lifetime).
  • Eliminate over-engineering using direct Server Actions and native platform capabilities.
  • Maintain an ultra-low latency, real-time notification engine for new content.

3. Architecture

Mira Prompts employs a strictly minimal, server-first architecture. It completely bypasses Redux, Zustand, and TanStack Query in favor of native Next.js Server Components and Server Actions.

A strictly secure flow prevents client-side tampering of Razorpay successes. The entire payment lifecycle is securely bridged via Server Actions.

6. Database Schema (Postgres)

Relational Integrity

Foreign keys enforce cascading deletes where appropriate, ensuring no orphaned tags or saves remain if a prompt is removed.

  • profiles: id (uuid), email, display_name, role (user/admin), subscription_status, last_notification_read_at.
  • prompts: id, slug, title, prompt (text), image_url, model, aspect_ratio, status (draft/published), is_featured, is_premium, created_by.
  • payment_history: id, user_id (fk), order_id, payment_id, amount, plan_type (monthly/yearly/lifetime).
  • support_tickets: id, user_id (fk), message, status (open/resolved).
  • tags & categories: Taxonomy tables with slugs. Mapped via prompt_tags junction table.

7. Security & Auth

7.1 Row Level Security (RLS)

Database queries executed from the client (or unprivileged server contexts) are restricted automatically by Postgres RLS:

  • prompts: Public can read where status = 'published'. Only admins can insert/update/delete.
  • support_tickets: Users can insert and read their own. Admins can read all and update status.
  • profiles: Users can update their own bio/display_name. role and subscription_status are protected from client mutation.

7.2 The requireAdmin() Guard

All admin-facing Server Actions wrap a highly secure guard that decodes the JWT and queries the profiles table to guarantee the role === 'admin' before proceeding.

8. Rendering Strategy

  • Route Interception & Parallel Routes: The prompt detail view uses Next.js @modal/(.)prompts/[slug]. This renders the prompt as a beautiful popover *over* the feed on soft navigation, but as a full standalone SEO page on hard refresh.
  • Streaming: Server components utilize Suspense boundaries. MasonryGrid loads image placeholders instantly.
  • Dynamic vs Static: The public feed is dynamic to account for personalized "Liked" and "Saved" states injected directly into the HTML payload.

9. Components & UI Lore ("The Silly Details")

Mira Prompts uses highly bespoke micro-interactions.

  • Auto-WebP Canvas: Instead of uploading 15MB PNGs to Supabase, prompt-form.tsx intercepts the file, paints it to an off-screen HTML5 Canvas, and compresses it to an 85% WebP blob before the upload even begins.
  • NEXT_REDIRECT Catch: Server actions throwing redirect() are cleanly caught via err?.message?.includes('NEXT_REDIRECT') in client boundaries to allow Next.js routing to function without throwing false alarms.
  • Mobile Image Perfection: Mobile modals use w-full h-auto on a raw <img> tag to prevent strict aspect-ratio clipping, matching the Pinterest aesthetic exactly.
  • Invisible Scrollbars: UI panels use [&::-webkit-scrollbar]:hidden [-ms-overflow-style:none] to maintain glassmorphism without native browser tracks.

10. Server Actions

Instead of building REST endpoints, the app relies strictly on typed Server Actions.

// Example: auth-actions.ts
export async function signInWithGoogle() {
  const supabase = await createClient()
  const { data, error } = await supabase.auth.signInWithOAuth({
    provider: 'google',
    options: { redirectTo: `${origin}/auth/callback` }
  })
  if (data.url) redirect(data.url)
}

Other actions include createPrompt, updatePrompt, verifyPayment, submitFeedback, and markNotificationsRead.
